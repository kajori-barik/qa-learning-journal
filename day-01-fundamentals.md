## 1. What is Software Testing?

Software testing is the process of evaluating a software application to identify defects and verify whether it meets specified requirements.

**Purpose:**
- Identify defects.
- Verify requirements.
- Improve software quality.
- Reduce risks.
- Ensure customer satisfaction.

## 2. Why is Software Testing Important?

- Helps identify bugs before release.
- Improves application reliability.
- Protects business data.
- Improves user experience.
- Reduces the cost of fixing defects later.

## 3. QA vs QC

**Quality Assurance (QA):**
- Process-oriented.
- Focuses on preventing defects.
- Improves development and testing processes.

**Quality Control (QC):**
- Product-oriented.
- Focuses on identifying defects.
- Checks whether the product meets requirements.

## 4. Verification vs Validation

**Verification:** Are we building the product right?

- Checks documents, requirements and design.
- Includes reviews and inspections.
- Generally involves static activities.

**Validation:** Are we building the right product?

- Checks whether the software meets user needs.
- Includes executing software tests.
- Generally involves dynamic activities.

## 5. SDLC – Software Development Life Cycle

Main phases:

1. Requirement Analysis
2. Planning
3. Design
4. Development
5. Testing
6. Deployment
7. Maintenance

## 6. STLC – Software Testing Life Cycle

Main phases:

1. Requirement Analysis
2. Test Planning
3. Test Case Design
4. Test Environment Setup
5. Test Execution
6. Test Closure

## 7. Seven Principles of Software Testing

1. Testing shows the presence of defects, not their absence.
2. Exhaustive testing is impossible.
3. Early testing saves time and money.
4. Defects cluster together.
5. Pesticide paradox: repeated tests may stop finding new defects.
6. Testing is context dependent.
7. Absence-of-errors fallacy: bug-free software can still fail user needs.

## 8. Error, Defect and Failure

**Error:** A human mistake.

**Defect/Bug:** A flaw in software caused by an error.

**Failure:** When software behaves incorrectly during execution.

Example:
- Developer enters an incorrect calculation formula: Error.
- Incorrect formula exists in the code: Defect.
- Application displays the wrong total: Failure.

## 9. Static vs Dynamic Testing

**Static Testing:**
- Does not require executing the application.
- Includes reviews, walkthroughs and inspections.
- Helps identify defects early.

**Dynamic Testing:**
- Requires executing the application.
- Checks actual software behavior.
- Includes functional and non-functional testing.

## 10. Manual vs Automation Testing

**Manual Testing:**
- Tester executes test cases manually.
- Useful for exploratory and usability testing.
- Requires human observation.

**Automation Testing:**
- Uses scripts and tools to execute tests.
- Useful for repetitive regression tests.
- Improves speed and repeatability.
